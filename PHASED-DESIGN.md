# Phased union-find for explicit graphs: design seeds from the FoF project

Written 2026-08-11 (Kale's framing + the paratreet2/FoF campaign's
measured lessons; companion evidence lives in paratreet2's design/
notes, cited inline). Context: this library's performance on explicit
file-read graphs has been poor; the FoF work — where edges are
generated by tree traversal — restructured the same computation into
LOCALITY PHASES and measured large wins. These are the transferable
design points for a phased rework, intended to seed a dedicated
session.

## 1. The phase structure (the core idea)

Three phases by edge locality, assuming vertices are partitioned with
locality (point 6):

1. PE-LOCAL: each PE owns a vertex subset and processes edges with
   both endpoints local — a PRIVATE sequential union-find. No atomics,
   no locks, no messages. Ends with a freeze: full path compression,
   per-PE representative labels.
2. PROCESS-LOCAL: edges spanning PEs of one process, processed against
   the FROZEN per-PE labels; each PE emits (rep, rep) merge pairs into
   a process buffer; ONE sequential union-find per process merges them
   (FoF's mergeBody). Shared memory, one lock-free deposit chain, no
   messages off-process.
3. CROSS-PROCESS: only these edges need communication, and they run
   over labels compressed by BOTH prior phases.

Correctness is the grouping theorem (paratreet2
design/phasea-reassignment.md section 2): union is associative and
idempotent, so ANY partition of the edge set by level is exact, and
duplicate edges across levels are harmless. FoF's phase-1-exact test
pattern (a single-process oracle) is the guard worth replicating.

## 2. Inter-phase path compression is the payoff mechanism

Each phase's merge collapses the label space the next phase sees —
fewer distinct labels means cheaper dedup, cheaper equality tests,
smaller maps. Honest caveat from measurement (design/
phaseab-balancing.md section 4): the label-COUNT reduction can be
small (FoF: <=4.5% of tips) while the WORK effect is what matters and
concentrates at partition boundaries — measure work, not label counts.

## 3. Representative-indirect relabeling (measured 18x)

Never rewrite per-vertex labels through hash probes. Keep the frozen
per-PE union-find array (root-direct after compression); apply every
later label map at ROOT granularity (thousands of probes per PE, not
millions), then materialize per-vertex labels as ONE indexed load.
FoF measured the relabel bracket 2.84 s -> 0.15 s at 2B/1920 PEs
(design/relabel-representative.md), roughly 18x, with counts exact.

## 4. Owner-encoded representatives + sliced map delivery

Encode representative ids with owner bits (process << k | index).
Then any global label map shards by owner: processor 0 (or the phase
root) sends each process ONLY its slice — direct sends when slices are
roughly 8-64 KB+, plain broadcast when the whole map is small
(measured policy, same note). This replaced a full-map broadcast +
1920 per-PE hash constructions.

## 5. Dedup rules that licence everything else

Exact keys (a lossy packed key silently dropped edges once — 32 bits
per endpoint is not enough); first-witness-wins with insert adjacent
to emit, so losing dedup state can only DUPLICATE an edge, never lose
one; duplicates idempotent at every merge. This is what makes work
movable (stolen work needs no dedup state shipped) and device-friendly
(sort-unique instead of live hash sets).

## 6. Partition for locality FIRST; expect bimodal boundaries

The strategy's win is proportional to the edge fraction local at each
level. File-read graphs arrive in arbitrary order: re-partition
vertices for locality (SFC order for geometric graphs, graph
partitioner otherwise), then BIN EDGES BY PHASE at load time. Measured
warning (design/phaseab-balancing.md section 16): locality splits are
BIMODAL across processes — typical processes had 88-100% of cost
internal, the HOT process had ~99% crossing, because balanced
partition boundaries cut through the dense region. Plan for the hot
owner: boundary-aware splits or work stealing; per-process
instrumentation, never process-0-only sampling (that artifact cost us
a wrong number for a day).

## 7. Termination by counting, not quiescence detection

The FoF pipeline's QD-free structure is a direct transfer: per-process
deposit chains (atomic counter on a process branch; last depositor
triggers the next phase; one closing reduction to the driver). The
existing find_components QD waits measured 87-220 ms of pure settle
on reconverse at scale, and the LCI idle-stall lives in exactly such
quiet windows. The just-merged labeling-scatter batching (one message
per peer chare + the live parent cache) is the same family of fix.

## 8. Scheduler discipline

Long drains block message service: slice long loops with a wall-clock
deadline per work unit and SELF-SEND re-entry (measured free at 80M);
pace every retry with a timer (1-2 ms); nodegroup entries are served
by any free PE — measured coordinator ping medians of 17-130 us at
ppn 15 during full phases (vs 12 ms burial at ppn 2), so per-process
responsiveness is real if SOME PE periodically reaches the scheduler.

## 9. Balance machinery (all measured in the FoF campaign)

- Cost-model the work units (edge counts per bucket are the graph
  analog of FoF's m2 geometric estimate) and claim costliest-first.
- Claim ONE unit at a time by CAS; the pick is advisory, the claim
  authoritative; one atomic per unit is the entire synchronization
  budget (FoF S1: within-process skew 1.45 -> 1.13 at 480 PEs).
- Vertex-subset ownership can itself be claimed/stolen within a
  process (the claimed subset belongs to the claimer for the whole
  phase — all downstream structures keyed to REALIZED ownership).
- Partition work into shippable batches for cross-process stealing;
  batch-granularity exclusivity for SHIPPING only, unit-granularity
  claims locally (exclusive batch claims measured a 3.7x regression).

## 10. Mode selection by scale

Keep a gather-to-one serial mode as the small/medium default: FoF
measured it flat at 0.01-0.02 s through 80M scales where the
distributed protocol paid 0.1-3.7 s of fixed latency and stall
exposure; the distributed machinery wins only past the serial
ceiling (~1e6+ edges at the root, memory- and wall-bounded). Choose
per run from the edge count, not by faith.

## Suggested first experiment for the new session

Take one of the poorly-performing file graphs; partition + bin edges
by phase; run phase 1+2 as above with the phase-3 edges fed to the
EXISTING library; compare against today's all-edges-to-the-library
baseline. That isolates the phase structure's value before any new
distributed protocol work.
